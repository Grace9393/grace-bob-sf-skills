# Salesforce Solution Architecture Style Rules

Use these rules for every section.

## Writing Style
- Write for architecture and delivery stakeholders.
- Prioritize architecture decisions and traceability over implementation detail.
- Do not include Apex/JS code.

## Required Elements Per Section
- Decision summary
- Rationale and trade-offs
- Salesforce capability mapping (cloud/features)
- Risks and mitigations
- Requirement trace IDs

## Diagram Expectations
- Provide clear Mermaid-ready logical descriptions.
- Ensure consistency between flows, ERD, integration, and security model.

## Context Budget
- Target each section at 450-1000 words.
- Use section memory summaries, not full prior section text.
